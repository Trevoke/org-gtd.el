CONTEXT: The checklists feature (PR #294) installs a GLOBAL hook,
org-gtd-checklist--maybe-reset-checkboxes, on org-after-todo-state-change-hook (via
org-gtd-mode). It clears checkboxes in ANY repeating heading subtree when it transitions
from a non-done to a done state with a non-zero repeater (mirrors org-auto-repeat-maybe).

RISK on upgrade to v5: a user who already has PRE-EXISTING repeating headings that contain
"- [ ]" checkbox items (anywhere in org, not just GTD files, since the hook is global)
will suddenly see those checkboxes auto-clear on completion. That is GTD-correct for
checklist habits, but it is a SILENT behavior change on their existing data.

PROPOSAL (from user, 2026-07-08): add an automated detection step to the v4->v5 upgrade
path. Existing convention is org-gtd-upgrade-v3-to-v4 in org-gtd-upgrades.el (version-ack
machinery). A org-gtd-upgrade-v4-to-v5 function (or similar) should scan the user files
(org-agenda-files) for repeating headings that contain checkbox items and WARN the user
(and/or explain the new auto-reset behavior), so the change is not silent. Consider an
opt-out / how to exempt a heading if that is desirable.

ORIGIN: PR #294 QA behavior-10 (the live-setup safety check we never ran in the sandbox).
Do this as part of shipping v5, alongside the CHANGELOG/upgrade notice.

HIGH IMPACT -- breaks the core live-preview value prop.

Repro (interactive, org-agenda-sticky=nil): open builder, set a filter to value A (e.g. area-of-focus=Work) -> preview narrows correctly. Then change the SAME filter to value B whose result includes items A had hidden (area-of-focus=Home) -> preview keeps showing A's result. Pressing RET (Preview) does NOT fix it. The badge/state DO update to B (state is correct); only the rendered agenda is stale. Adding a filter (nil->value) and clearing one (value->nil) both work; only value->value fails.

Evidence:
- Badge shows the new value (state correct).
- (with-current-buffer "*Org Agenda*" ...) still contains the OLD result after the change + RET -> the agenda BUFFER itself is not rebuilding. No stray agenda buffers.
- Headless repro of the same two renders (Work then Home) rebuilds correctly (sticky=nil), so the DSL/compile/skip-functions are fine. The failure is interactive-only, in the live-preview render path.

Two compounding faults:
1. The re-render (org-gtd-view-show -> (org-agenda nil "g"), run from a debounced idle-timer while a transient is active) does not actually rebuild the *Org Agenda* buffer. Likely tangled with the window/transient fight (see sibling yak) or org-agenda buffer reuse under the same dispatch key.
2. org-gtd-view-manager--preview-now sets --preview-last to the new spec after a render that returned without error, even though the buffer didn't rebuild. So --preview-changed-p then reports 'unchanged' and RET (--preview) skips re-rendering -> stale view is unrecoverable.

Fix directions: make the preview force a genuine rebuild (don't rely on org-agenda reuse; e.g. render into a dedicated buffer/window or force redo); make RET (explicit --preview) BYPASS the changed-p guard and always rebuild; only update --preview-last when a rebuild actually happened.

DECISION (2026-07-08): KEEP the wrapper subtree as the default and ONLY shape.
Rationale (this is the "how it hooks into other work" answer): the wrapper heading is the
hinge of the insert -> organize-as-habit -> auto-reset chain. insert pastes template as a
HEADING + "- [ ]" items; organizing that heading as a habit puts a repeater ON the
heading; the reset hook (org-reset-checkbox-state-subtree) clears the checkboxes in that
heading subtree on each repeat. No wrapper => nothing carries the repeater and nothing for
the reset hook to scope to. User chose plain "keep wrapper" (NOT the prefix-arg bare-items
variant), so the augment-existing-task case is intentionally unsupported.

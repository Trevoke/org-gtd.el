# Book 1: Getting Things Done (David Allen) — Recommended User Workflows

Source: `docs/source-material/Getting Things Done (David Allen) (z-library.sk, 1lib.sk, z-lib.sk).txt` (8867 lines).
Note: the text is the **revised edition** (uses capture/clarify/organize/reflect/engage and the
"Horizons" terminology; includes chapters 14–15), not the 2001 first edition. Line citations refer
to this file.

A "workflow" here = a prescribed flow, sequence of questions, mindset shift, or order of operations
that could become an acceptance test for a GTD application. Allen's worked examples (dinner-out
story, kitchen-mess story, client anecdotes) are treated as illustrations only, not separate
workflows.

The five-step master loop itself — (1) capture, (2) clarify, (3) organize, (4) reflect, (5) engage
(lines 999–1011) — is the umbrella for everything below. Allen explicitly prescribes doing the five
steps **separately, not all at once** ("one of the major reasons many people haven't had a lot of
success with getting organized is simply that they have tried to do all five steps at one time",
lines 1035–1037). Each workflow below is one of the discrete flows inside that loop.

## Setup

### B1-W-01 — Initial full-scale implementation (time, space, tools)
- **Trigger/situation:** User decides to install the GTD system from scratch.
- **Steps in order:**
  1. Block out a dedicated chunk of time — ideal is **two whole days, back to back**, preferably a
     weekend/holiday with interruptions blocked; capturing alone can take ~1–6 hours, clarifying
     another ~8 (lines 2348–2372). Partial implementation still pays off, but one contained period
     is strongly preferred ("you can't cross a chasm in two small jumps").
  2. Set up a dedicated physical workspace: writing surface + in-tray at minimum; identical/
     interchangeable satellite system at home; a micro-office in transit; **never share a workspace**
     (lines 2376–2420).
  3. Acquire the basic processing tools: ≥3 paper trays, stack of plain paper, pen, Post-its, clips,
     stapler, tape, rubber bands, automatic labeler, file folders, a calendar, wastebasket/recycle
     bins, plus whatever capture/list tools are already in use (lines 2432–2460).
  4. Ensure the general-reference filing system is in place *before* processing (see B1-W-02) —
     "The filing system at hand is one of the first things I assess before beginning the workflow
     process in anyone's office" (lines 2550–2558).
  5. **Clear the decks**: handle or park (with a reminder) any commitment that would interrupt the
     session, so full attention is available (lines 2648–2658).
- **Done when:** dedicated time blocked, workspace functional, tools at hand, filing system ready,
  no competing commitments pulling attention; ready to gather all open loops into one place.
- **Cadence:** one-time (revisited when upgrading the system).
- **Citations:** lines 2302–2658.

### B1-W-02 — General-reference filing flow (the <60-second standard)
- **Trigger/situation:** Any nonactionable item with potential future value appears (during
  processing or ad hoc).
- **Steps in order:**
  1. Decide it needs no next action but has reference value.
  2. File it in **less than one minute**: make a label (with the auto-labeler), put it in its own
     plain folder, drop the folder in a single **A–Z alphabetical** general-reference system (not
     multiple systems, not organized by project/area) (lines 2579–2601). Digital equivalents: create
     the folder/directory instantly and drag the item in.
  3. Structural success factors to keep this possible: files within swivel distance; plenty of fresh
     folders at hand; drawers **less than three-quarters full**; typeset labels (lines 2587–2621).
  4. **Purge files at least once a year** (a "purge day" can be put in the tickler file)
     (lines 2629–2631).
- **Done when:** "It should take you less than one minute to pick something up out of your in-tray
  ... and finish storing it in a trusted system" (line 2581); otherwise the user will stack instead
  of file and resist emptying "in".
- **Cadence:** continuous; purge annually.
- **Citations:** lines 2550–2644; reinforced 3806–3818.

## Capture

### B1-W-03 — Initial physical gathering ("corralling your stuff")
- **Trigger/situation:** Start of implementation (after B1-W-01); first half of the capture phase.
- **Steps in order:**
  1. Search the physical environment for **anything that doesn't permanently belong where it is,
     the way it is** and put it in the in-tray (line 2711).
  2. Apply the stays-put test — four categories remain in place with no action: **supplies,
     reference material, decoration, equipment** — but only if they are exactly where/how they
     should be; otherwise they too go to "in" (lines 2714–2738).
  3. Work locations in order: desktop → desk drawers → countertops → inside cabinets → floors,
     walls, and shelves → equipment/furniture/fixtures → other locations (home, car, etc.)
     (lines 2788–2860).
  4. Handling rules along the way:
     - Item too big for the tray → write a representative note on letter-size paper, **date it**
       (lines 2755–2757).
     - Pile too big → stacks around/below the in-tray, visually distinct from everything else
       (line 2759).
     - Obvious trash → toss immediately (line 2761); if unsure what it is, put it in "in" and decide
       later — capturing and clarifying require different mind-sets and are done separately
       (line 2763).
     - Resist the **purge-and-organize bug**: if an area needs cleanup, write a note ("Purge
       four-drawer cabinet") and put the note in "in" (lines 2775–2777).
     - Existing lists/organizers → treated as items still to be processed, into "in" (line 2779).
     - "Can't lose that!" items → if truly must be handled before implementation finishes, do it
       now; else into "in"; last resort, a small "emergency" stack (lines 2781–2785).
  5. This is **not** minimalism: keep whatever you want, as long as embedded actions are captured
     (lines 2863–2865).
- **Done when:** every physical nook holds only supplies/reference/decoration/equipment that are
  where and how they should be; everything else (or a note representing it) is in "in".
- **Cadence:** one-time at setup; mini version weekly (see B1-W-23 "Collect Loose Papers").
- **Citations:** lines 2670–2865.

### B1-W-04 — The mind sweep (mental gathering with trigger list)
- **Trigger/situation:** Physical gathering complete; head still holds unrepresented commitments.
- **Steps in order:**
  1. Ask: "What has your attention that isn't represented by something already in your in-tray?"
     (line 2871).
  2. Write **each thought/idea/project on its own separate sheet of paper** (one item per sheet, to
     enable item-by-item processing later) and toss into "in" (lines 2873).
  3. Go for **quantity, not quality** — capture everything from "Implement global climate change"
     to "I need cat food"; junk can be tossed later (lines 2875–2877).
  4. Then review the **Incompletion Triggers list** item by item to jog loose anything forgotten —
     professional triggers (projects started/not completed, commitments to others, communications,
     writing to finish, financial, planning, organization development, marketing, administration,
     systems, meetings, professional development, waiting-fors ...) and personal triggers; each hit
     gets its own sheet into "in" (lines 2880–3610).
- **Done when:** nothing else shows up as a reminder in the mind ("How will you know when there's
  nothing left? When nothing else shows up as a reminder in your mind", line 6151). Expected
  duration 20–60 minutes after physical gathering (line 2875).
- **Cadence:** full version at setup; "Empty Your Head" repeated in every Weekly Review.
- **Citations:** lines 2869–3610; completeness standard at 6147–6161.

### B1-W-05 — Ongoing capture habit
- **Trigger/situation:** Any new commitment, idea, or input occurs, anywhere, anytime.
- **Steps in order:**
  1. The moment a "should / need to / ought to" attaches to something, it is an open loop
     (line 1065) — write it down/record it into an in-tray-equivalent capture tool the moment it
     occurs; capture tools must be as ubiquitous "as your toothbrush" (lines 1141).
  2. Keep **as few capture locations as you can get by with, as many as you need** — funnel all
     inputs through minimal channels (lines 1144–1148).
  3. **Empty the capture tools regularly** — emptying ≠ doing; it means deciding what each item is
     and organizing it into the system; never leave or return things to "in" (lines 1159–1161).
- **Done when:** everything potentially meaningful is in a trusted external bucket, not the head
  ("Keep everything in your head or out of your head. If it's in between, you won't trust either
  one", line 1137), and the buckets reach empty regularly (every "day or two", line 3673).
- **Cadence:** continuous; emptying at least every couple of days.
- **Citations:** lines 1043–1171; chapter 11 reinforcement 6147–6161.

## Clarify

### B1-W-06 — The per-item processing decision tree (the core algorithm)
- **Trigger/situation:** Processing any single item from any "in" (paper, e-mail, note, thought).
- **Steps in order (book's questions verbatim):**
  1. **"What is it?"** — identify what the item actually is/means (lines 1190–1192).
  2. **"Is it actionable?"** — "There are two possible answers for this: yes and no" (lines 1204–1206).
  3. **If NO**, three possibilities (lines 1208–1210, 3733–3742):
     - **Trash** — toss/shred/recycle ("When in doubt, throw it out" or "When in doubt, keep it" —
       either policy is fine, lines 3754–3756).
     - **Incubate** — "There's nothing to do on this now, but there might be later" → Someday/Maybe
       list, or a dated reminder on the calendar/tickler file (lines 3773–3803).
     - **Reference** — file it immediately in the reference system (B1-W-02) (lines 3806–3818).
  4. **If YES**, two things must be determined (lines 1212–1228):
     - **Is it a project?** If more than one action step is needed to reach the committed outcome,
       capture the outcome on the **Projects list** (lines 1226, 4018–4024).
     - **"What's the next action?"** — "the next physical, visible activity that needs to be
       engaged in, in order to move the current reality of this thing toward completion"
       (lines 1228, 3834). It must be the absolute next *physical* thing — "set meeting" is not a
       next action; "e-mail X to propose times" is (lines 3897–3905). If the needed action is "decide",
       determine the physical activity that enables the decision (get information, draft ideas)
       (lines 3909–3915).
  5. **Once the next action is decided, three options** (lines 1244–1250, 3919–3927):
     - **Do it** — if it takes less than two minutes (B1-W-08).
     - **Delegate it** — "Am I the right person to do this?" If no, hand it off (B1-W-09).
     - **Defer it** — write it down and organize it onto the appropriate Next Actions list /
       calendar (B1-W-12/13).
- **Done when:** the item has been dispatched into exactly one of: trash, Someday/Maybe, tickler/
  calendar reminder, reference, done (≤2 min), Waiting For (delegated), calendar, or a Next
  Actions list — plus a Projects-list entry if it's a multi-step outcome. The item is *out of "in"*.
- **Cadence:** every time "in" is processed.
- **Citations:** decision tree overview 1187–1251; full chapter 6 treatment 3614–4034.

### B1-W-07 — Processing-session discipline (getting "in" to empty)
- **Trigger/situation:** Sitting down to process an in-tray / e-mail inbox to zero.
- **Steps in order:**
  1. Understand the goal: emptying "in" "doesn't mean actually doing all the actions ... It just
     means identifying each item and deciding what it is, what it means, and what you're going to
     do with it" (line 3620).
  2. Apply the three rules (lines 3646–3652):
     - **"Process the top item first"** — everything gets processed equally; no cherry-picking
       (lines 3658–3666). ("Emergency scanning" is allowed as a separate, named activity but is
       explicitly *not* processing, lines 3669–3673.)
     - **"Process one item at a time"** — take only the top item out; forces the decision (lines
       3688–3698; exception: 2–3 items at once for personalities that need to shift focus, never
       avoiding a decision for more than a minute or two, lines 3701–3705).
     - **"Never put anything back into 'in'"** — one-way path out; the first time you pick something
       up, decide what to do about it and where it goes (lines 3709–3711).
  3. LIFO vs FIFO doesn't matter much if you reach the bottom in a reasonable period — except for a
     large **e-mail backlog**, where last-in-first-out is more efficient because of discussion
     threads (lines 3676–3684).
- **Done when:** "in" is physically/digitally empty and every item has gone through B1-W-06.
- **Cadence:** at least every day or two (line 3673).
- **Citations:** lines 3614–3713.

### B1-W-08 — The two-minute rule (do-it-now in flow)
- **Trigger/situation:** A next action has just been decided during processing (or any engagement
  with new input).
- **Steps in order:**
  1. Estimate: can the action be done in **two minutes or less**?
  2. If yes, **"do it when you first pick the item up"** — even if it's not high priority — because
     two minutes is "the efficiency cutoff": storing and tracking it would take longer than doing
     it (lines 3923, 3932–3936).
  3. If the action completes the loop, done; if not, **clarify the next action on it** and do/
     delegate/defer that per the same criteria (line 3964).
  4. The cutoff is a guideline: extend to 5–10 minutes with a long open window, shorten to 1 minute
     or 30 seconds when time is tight (line 3946).
  5. Scope limit: apply primarily when engaging new input — don't spend the whole day hunting
     two-minute actions (line 3970).
- **Done when:** sub-two-minute actions are executed immediately and never tracked ("There's
  nothing you really need to track about your two-minute actions—you just do them", line 3964).
- **Cadence:** continuous, inside every processing pass.
- **Citations:** lines 1246, 3932–3970.

### B1-W-09 — Delegation handoff and tracking
- **Trigger/situation:** Next action takes >2 minutes and "Am I the best person to be doing it?"
  answers no (line 3975). Delegation can also go upstream/sideways (boss, partner, other dept).
- **Steps in order:**
  1. Hand it off in a systematic format, in this **preference order**: (a) e-mail; (b) written
     note/over-note routed with the item; (c) text/voice mail; (d) item on the Agenda list for the
     next real-time conversation; (e) direct real-time interruption (last resort) (lines 3979–3993).
  2. **Track the handoff** on a **Waiting For** list if you care whether it happens (lines
     3995–3997); e-mail variant: save a cc/bcc copy into an `@WAITING FOR` folder (lines 4358–4366).
  3. If the ball is already in someone else's court (e.g. waiting for documents), record it the same
     way: "Waiting for X from Y" (lines 3999).
  4. **Record the date on everything handed off** — "of all the categories in your personal system,
     the most crucial one to keep tabs on" (line 4001); include any agreed due date (line 4310).
- **Done when:** the item lives on the Waiting For list (with date) and nothing about it remains in
  "in" or in the head.
- **Cadence:** continuous; list reviewed in Weekly Review and before meetings with the people
  involved (line 4308).
- **Citations:** lines 1248, 3973–4001, 4294–4312.

### B1-W-10 — Project identification (closing out a processing pass)
- **Trigger/situation:** Last step in getting to the bottom of "in"; also whenever a defined action
  won't complete the commitment.
- **Steps in order:**
  1. Shift perspective from single actions to outcomes: scan generated actions for ones that won't
     finish the commitment ("Call Frank about the car alarm" → there's still more after the call)
     (lines 4020–4022).
  2. For each, write the **outcome** on the Projects list — "any outcome you're committed to
     achieving that will take more than one action step to complete" and achievable within a year
     (lines 4022, 1280).
  3. The list is "not to reflect your priorities but just to ensure that you've got placeholders for
     all those open loops" (line 4024); no ordering by size/priority needed (line 1320).
  4. May be done during processing or after action lists are set up — "It just needs to be done at
     some point, and it must be maintained" (line 4032).
- **Done when:** every multi-step open loop has a stake-in-the-ground entry on the Projects list
  (expect 30–100, line 4026).
- **Cadence:** continuous + verified weekly.
- **Citations:** lines 1226, 1278–1324, 4018–4034.

## Organize

### B1-W-11 — The bucket system with hard edges
- **Trigger/situation:** Organizing the results of clarifying; building the system's structure.
- **Steps in order:**
  1. Maintain exactly these primary categories: **Projects list, project support material, calendar
     actions and information, Next Actions lists, Waiting For list, reference material,
     Someday/Maybe list** — plus trash (lines 4077–4092; outer ring of the workflow diagram,
     1262–1264).
  2. Keep the categories "pristinely distinct ... visually, physically, and psychologically
     separate" — blending them destroys the system (reference mixed with read-me → numbness;
     calendar items on action lists → distrust of calendar; inactive projects on Projects list →
     dilution; Waiting For on action lists → nonproductive rethinking) (lines 4097–4119).
  3. Tooling is just **lists and folders** (paper or digital); "Being organized means simply that
     where something is matches what it means to you" (lines 1258, 4059, 4123–4141).
  4. Do **not** impose priority scaffolding on lists — prioritize intuitively against the whole
     inventory at run time (line 4139).
- **Done when:** every clarified item lives in exactly one bucket whose meaning matches the user's
  agreement with it.
- **Cadence:** structural; enforced continuously.
- **Citations:** lines 1254–1266, 4046–4141.

### B1-W-12 — Calendar discipline ("sacred territory")
- **Trigger/situation:** Deciding whether a deferred action belongs on the calendar.
- **Steps in order:**
  1. Only **three things** go on the calendar: **time-specific actions** (appointments),
     **day-specific actions** (must happen that day, anytime), **day-specific information**
     (directions, lead-time triggers, "call after she returns") (lines 1350–1364).
  2. "Those three things are what go on the calendar, and nothing else!" — **no daily to-do lists
     on the calendar**, for two stated reasons: constant new input reshuffles the day, and
     non-mandatory items dilute the true hard landscape (lines 1376–1380).
  3. "If you write something there, it must get done that day or not at all. The only rewriting
     should be for changed appointments" (line 1380).
  4. Everything else that must merely be done as soon as possible goes to Next Actions lists
     (lines 4153–4165). An informal "if I have time today I'd like to..." list is allowed but must
     never be confused with the have-tos (line 1382).
- **Done when:** the calendar shows only the hard landscape and is trusted at a glance.
- **Cadence:** continuous.
- **Citations:** lines 1346–1382, 4153–4165, 2498–2506.

### B1-W-13 — Context-sorted Next Actions lists
- **Trigger/situation:** Deferred actions (>2 min, mine, not date-bound) need organizing; more than
  ~25 of them exist.
- **Steps in order:**
  1. Sort action reminders **by context** — the tool/location/situation required: common headings
     are **Calls, At Computer, Errands, At Office, At Home, Anywhere, Agendas (per person/meeting),
     Read/Review** (lines 4180–4198).
  2. Granularity depends on (1) how many actions you track, (2) how often contexts change
     (line 4173). A single list is fine for ~25 actions; 50–150 requires subdivision (lines
     1401, 4175).
  3. Conventions: phone numbers written alongside Calls items (line 4204); Errands items can carry
     sublists (hardware store → items) (line 4232); separate Agenda lists for each boss/partner/
     assistant/child/standing meeting (lines 4248–4266); Read/Review reserved strictly for
     >2-minute reading, with the material itself as the reminder (lines 4268–4288).
  4. Context sorting also *forces* the next-physical-action decision (you can't file it on a list
     until you know which tool it needs) (line 5354). Custom contexts are encouraged ("Before
     Trip", "Brain Gone", "Less Than 5-Minute") (lines 5359–5365).
- **Done when:** at any moment, in any context, the user can see exactly the actions doable there
  and nothing else.
- **Cadence:** structural; reviewed per B1-W-22.
- **Citations:** lines 1385–1401, 4169–4290, 5338–5367.

### B1-W-14 — Waiting For list management
- **Trigger/situation:** Anything delegated or dependent on others.
- **Steps in order:**
  1. Track deliverables (not necessarily action steps) others owe you, each entry **with the date
     requested and any due date** (lines 4302, 4310).
  2. Review the list "as often as you need to" and decide whether to take a follow-up action (check
     status, light a fire) (line 4302).
  3. Keep it at hand alongside Next Actions lists — responsibility ping-pongs between Waiting For,
     Read/Review, and your action lists as a project advances (line 4306).
  4. Have it visible when meeting anyone responsible for an item, to follow up early and gracefully
     (line 4308).
- **Done when:** the list is "the complete inventory of everything you care about that other people
  are supposed to be doing" (line 4312).
- **Cadence:** continuous + Weekly Review pass.
- **Citations:** lines 1343, 4294–4312.

### B1-W-15 — E-mail "in" to zero
- **Trigger/situation:** Processing the e-mail inbox; managing actionable e-mail.
- **Steps in order:**
  1. Process the inbox per B1-W-06/07: delete what you can; file keepers into reference folders;
     do ≤2-minute replies immediately (≈30% of actionable e-mail, line 3968).
  2. Create **`@ACTION`** (longer-than-two-minute e-mails you must act on) and **`@WAITING FOR`**
     (things others owe you, incl. bcc copies of your delegations) folders, prefix-sorted to the top
     of the folder list (lines 4354–4366).
  3. Drag every remaining actionable/waiting message into those folders, leaving "in" **empty**
     ("getting 'in' empty doesn't mean you've handled everything", line 4370).
  4. Treat `@ACTION` "as an extension of your At Computer list" — review it just like an action
     list before ending the day or going off-plan; dispersed reminders are fine **only if all
     locations are reviewed equally** (lines 4381–4383).
- **Done when:** e-mail "in" is empty; anything residing there is by definition unprocessed new
  input (line 4368).
- **Cadence:** to zero at least every day or two; folders reviewed like action lists.
- **Citations:** lines 4350–4385; testimonial/rationale 3938–3968.

### B1-W-16 — Someday/Maybe incubation
- **Trigger/situation:** Item is not actionable now but might be later; or a current project loses
  traction.
- **Steps in order:**
  1. Park "projects I might want to do, but not now" on a **Someday/Maybe list** (lines 1421–1461,
     4669–4673); special-interest sublists (Books to read, Trips to take, Recipes to try ...) are
     encouraged (lines 1463–1483, 4714–4736).
  2. Feed it from two sources besides "in": an inventory of creative imaginings, and a **reassessment
     of the current Projects list** — any project that won't get attention for months moves here
     (lines 4681–4707).
  3. **Review the list in the Weekly Review** — reactivate items to Projects, delete dead ones, add
     new possibilities (lines 1461, 5178).
  4. Anti-pattern called out: "Hold and Review" piles that are held but never reviewed go numb; the
     category's value "disappears if you don't put your conscious awareness back onto it with some
     consistency" (lines 4741–4755).
- **Done when:** every not-now commitment is parked where it will reliably resurface, freeing the
  Projects list for rigorous action focus.
- **Cadence:** weekly review of the list (some sublists only when the urge strikes).
- **Citations:** lines 1415–1483, 4656–4755.

### B1-W-17 — Calendar as future-options trigger (decide-not-to-decide)
- **Trigger/situation:** Something needs reassessment at a known future date rather than now.
- **Steps in order:**
  1. Put a **day-specific information** entry on the calendar for the chosen date, for any of:
     **triggers for activating projects** (events with lead time, recurring preparations, key
     dates), **events you might want to participate in**, **decision catalysts** (hire/fire,
     merge/acquire, change career...) (lines 4758–4822).
  2. When the day arrives and the trigger fires, either activate it (add to Projects list) or
     re-decide (lines 4772).
  3. Principle: "It's OK to decide not to decide—as long as you have a decide-not-to-decide system"
     (lines 3797, 4804).
- **Done when:** the future option is off the mind, with a trusted safety net guaranteeing
  re-presentation on the right day.
- **Cadence:** ad hoc creation; daily calendar review surfaces them.
- **Citations:** lines 1485–1487, 3789–3803, 4758–4822.

### B1-W-18 — Tickler file daily ritual (43 folders)
- **Trigger/situation:** Physical/dated reminders that should "mail themselves" to the future; daily
  system maintenance.
- **Steps in order:**
  1. Set up 43 folders: 31 daily ("1"–"31") + 12 monthly, arranged perpetually starting from
     tomorrow's date (full rotation algorithm at lines 4847).
  2. File anything you want to see on a given future date into that day's/month's folder (travel
     docs, agendas to re-see, invoices held for payment, birthday reminders) (lines 4827–4843).
  3. **Every day, empty the next daily folder into the in-tray**, then refile the empty folder at
     the back (it now represents the same date next month); on month rollover, distribute the
     monthly folder's contents into dailies (line 4847).
  4. "You must check and update it every day. If you forget to empty the daily file, you won't
     trust the system"; before travel, check the folders for the days you'll be away (line 4861).
- **Done when:** the day's folder is empty into "in" each morning; ritual costs "one second per
  day" (line 4845).
- **Cadence:** **daily**, without exception.
- **Citations:** lines 1485–1489, 4825–4861.

### B1-W-19 — Checklists as external mind
- **Trigger/situation:** Recurring procedures, unfamiliar responsibilities, or "fuzzy" intentions
  ("exercise more", "keep team morale up") that aren't single projects/actions.
- **Steps in order:**
  1. First, extract any **inherent project and next action** from the fuzzy item ("Exercise more
     regularly" → project "Set up regular exercise program" + action "Call Sally re gyms")
     (lines 4905–4908).
  2. What remains becomes a **checklist** to review at the right recurrence: life/job areas-of-focus
     blueprints, travel checklists, weekly-review checklist, event-production components, year-end
     activities, etc. (lines 4913–5001).
  3. The more novel the situation, the more checklist control is required; retire checklists once
     the area is on "cruise control" (lines 4958–4972).
  4. Be ready to create and eliminate checklists ad hoc; keep an easily accessed, pleasant place for
     new lists (line 5004).
- **Done when:** every recurring or fuzzy commitment is either a project+action or a checklist with
  a defined review trigger.
- **Cadence:** per-checklist (situational to quarterly).
- **Citations:** lines 4863–5006.

### B1-W-20 — Uncovering hidden projects
- **Trigger/situation:** Completing/refreshing the Projects list; suspicion the inventory is
  incomplete.
- **Steps in order — sweep three areas (lines 4439–4448):**
  1. **Current activities**: scan calendar (past and upcoming meetings/trips/events) and action
     lists for actions whose larger outcome isn't yet a project ("Call Mario re: fund-raising
     event" → project "Finalize the fund-raiser"); check physical artifacts (contracts in
     briefcase, broken watch) (lines 4451–4457).
  2. **Higher-horizon interests and commitments**: review accountabilities, goals, plans, and
     longer-term personal pulls for "look into..." projects (lines 4459–4463).
  3. **Current problems, issues, and opportunities**: "When is a problem a project? Always."
     Problems, process improvements, and creative/capacity-building desires each become projects
     with next actions (lines 4465–4479).
- **Done when:** Projects list "truly capture[s] all the commitments you have that will require
  more than one action to get done" (line 5606).
- **Cadence:** at setup and as part of Weekly Review / Areas-of-Focus review (every 1–3 months for
  the latter, line 5632).
- **Citations:** lines 4439–4480, 5606–5638.

### B1-W-21 — Project support material handling
- **Trigger/situation:** Plans, notes, and ad hoc ideas accumulate around projects.
- **Steps in order:**
  1. Never use support material as the action reminder — first put the project on the Projects
     list, then put actions/waiting-fors on their lists; pull support material only when doing the
     action or reviewing the project (lines 4536–4548).
  2. Capture random project thoughts wherever they occur (capture tools), then route them to the
     project's home: attached notes on the list item, dedicated e-mail/app folders, paper folders,
     or notebook pages (lines 4555–4581, 5821–5825).
  3. Review project plans/support during the Weekly Review to harvest new actions; purge stale
     notes (lines 4548–4550, 4583–4585).
- **Done when:** support material is organized by project/theme, visible enough to be reviewed,
  and contains zero un-extracted action reminders.
- **Cadence:** continuous capture; weekly harvest.
- **Citations:** lines 1327–1335, 4532–4585.

## Reflect

### B1-W-22 — Daily orientation review (calendar first, then context lists)
- **Trigger/situation:** Starting the day; finishing any calendar item; any free window.
- **Steps in order:**
  1. **Look at the calendar first** (and the daily tickler folder) — see the "hard landscape" and
     the day's time/space parameters (lines 5064–5066, 1522).
  2. Good habit: as soon as you conclude an action on your calendar, "check and see what else
     remains to be done" (line 1522).
  3. **Then your action lists** for the current context — evaluate predefined options against
     incoming work (lines 5070–5082, 1530).
  4. Review other lists situationally: agendas before talking to that person, Errands before going
     out, Projects list when the boss pops in (lines 5052, 5088–5090).
  5. Governing question: "When do I need to see what, in what form, to get it off my mind?"
     (line 1029); time cost is "a few seconds a day ... two seconds here, three seconds there"
     (lines 5054–5060).
- **Done when:** the user trusts that day-level choices are made against a current calendar and
  context-appropriate lists.
- **Cadence:** **daily** and continuous (most-reviewed: calendar; next: action lists; Projects/
  Waiting For/Someday-Maybe only often enough "to stop you from wondering about them",
  line 1532).
- **Citations:** lines 1518–1532, 5048–5090.

### B1-W-23 — The Weekly Review (Get Clear → Get Current → Get Creative)
- **Trigger/situation:** Once a week; the "critical success factor" and "master key" sustaining the
  whole system (lines 1548, 1572, 5108).
- **Definition:** "whatever you need to do to get your head empty again and get oriented for the
  next couple of weeks ... until you can honestly say, 'I absolutely know right now everything I'm
  not doing but could be doing if I decided to'" (line 5129).
- **Steps in order (book's checklist, lines 5134–5181):**
  - **Get Clear**
    1. *Collect Loose Papers and Materials* — gather strays into the in-tray (line 5138).
    2. *Get "In" to Empty* — process all notes, e-mails, texts, voice mails to zero (line 5140).
    3. *Empty Your Head* — write out any uncaptured new projects/actions/waiting-fors/someday-maybes
       (line 5142).
  - **Get Current**
    4. *Review "Next Actions" Lists* — mark off done items; record further actions (line 5149).
    5. *Review Previous Calendar Data* — past 2–3 weeks for remaining/emergent actions and reference
       (line 5151).
    6. *Review Upcoming Calendar* — capture projects/preparations for upcoming events (line 5153).
    7. *Review "Waiting For" List* — follow-ups, check off received items (line 5155).
    8. *Review "Projects" (and "Larger Outcome") Lists* — one by one, **ensure at least one current
       kick-start action for each is in the system**; browse project plans/support material
       (line 5157).
    9. *Review Any Relevant Checklists* (line 5159).
  - **Get Creative**
    10. *Review "Someday/Maybe" List* — activate, delete, add (line 5178).
    11. *Be Creative and Courageous* — capture any new ideas into the system (line 5180).
- **Timing guidance:** block ~two hours; ideal slot is early afternoon of the last workday (week
  still fresh; people still reachable; clean decks for the weekend) (lines 5189–5197); summarized
  in ch. 2 as "Gather and process all your stuff. Review your system. Update your lists. Get
  clean, clear, current, and complete." (lines 1554–1562).
- **Done when:** the user can honestly make the "I know everything I'm not doing" statement; all
  lists current; head empty.
- **Cadence:** **weekly**.
- **Citations:** lines 1536–1574, 5108–5237.

### B1-W-24 — Higher-horizon ("bigger picture") reviews
- **Trigger/situation:** Operational levels (Ground/Horizon 1) are under control; or longer-horizon
  questions begin pulling on attention.
- **Steps in order:**
  1. At appropriate (longer) intervals, review Horizons 2–5: areas of focus/accountability (use an
     **Areas of Focus list**, professional + personal, as a project-generating trigger every **one
     to three months**, lines 5632); 1–2-year goals; 3–5-year vision; purpose/principles
     (lines 5241–5257, 5648–5704).
  2. Capture whatever the review provokes; process those notes: trash, Someday/Maybe ("Dreams and
     Goals I Might Get Around to"), or a project with a next action (lines 5712–5728).
  3. Direction of travel is **bottom-up**: get Ground and Horizon 1 current first — "Trying to
     manage from the top down when the bottom is out of control may be the least effective
     approach" (lines 5566–5598).
- **Done when:** "You need to assess your life and work at the appropriate horizons, making the
  appropriate decisions, at the appropriate intervals, in order to really come clean" (line 5257).
- **Cadence:** Areas of Focus every 1–3 months; higher horizons at user-determined longer intervals.
- **Citations:** lines 5241–5279, 5515–5728.

## Engage

### B1-W-25 — Four-criteria model for choosing actions in the moment
- **Trigger/situation:** "At 3:22 on Wednesday, how do you choose what to do?" — any moment of
  discretionary time.
- **Steps in order (criteria applied in this order, lines 1597–1601, 5322–5330):**
  1. **Context** — what *can* you do here, with the tools at hand? (Filter to the matching
     context list.) (lines 1603, 5338–5354)
  2. **Time available** — what fits before the next hard commitment? (lines 1611, 5371–5377)
  3. **Energy available** — match remaining options to current mental/physical horsepower; keep an
     inventory of low-horsepower tasks for low states (lines 1613, 5381–5405).
  4. **Priority** — "Out of all my remaining options, what is the most important thing for me to
     do?" — an intuitive judgment informed by the higher horizons (lines 1615–1617, 5411–5423).
- **Done when:** the user can "feel as good about what you're not doing as about what you are doing
  at that moment" (line 1607), choosing from trust instead of hope.
- **Cadence:** continuous, every action choice.
- **Citations:** lines 1588–1617, 5320–5423.

### B1-W-26 — Threefold model for identifying daily work
- **Trigger/situation:** Understanding/balancing what you're doing at any moment of the workday.
- **The three activities (lines 1620–1638, 5429–5439):**
  1. **Doing predefined work** — working from Next Actions lists and calendar.
  2. **Doing work as it shows up** — ad hoc demands; choosing them is "deciding by default that
     these things are more important than anything else you have to do at those times" (line 1634).
  3. **Defining your work** — processing in-trays/notes, breaking projects into actions, populating
     lists.
- **Prescribed flow/mindset:**
  - Doing unexpected work must be **a conscious choice against the known inventory**, not the path
    of least resistance: "The constant sacrifices of not doing the work you have defined on your
    lists can be tolerated only if you know what you're not doing" (line 5465).
  - Interruption handling: capture/"bookmark" the new input (a note into "in"), keep or consciously
    switch focus, return cleanly — "There are no interruptions—there are only mismanaged inputs"
    (lines 5467–5475, 5485–5509).
- **Done when:** all three activities get deliberate time; the in-tray never rots long enough that
  its contents resurface as emergencies (line 5477).
- **Cadence:** continuous, daily.
- **Citations:** lines 1620–1638, 5425–5513.

### B1-W-27 — Six-level (Horizons) model for reviewing work, bottom-up
- **Trigger/situation:** Deciding what your work *is*, so priority judgments have grounding.
- **The levels (lines 1645–1656, 5517–5529):** Horizon 5 purpose/principles; Horizon 4 vision
  (3–5 yr); Horizon 3 goals (1–2 yr); Horizon 2 areas of focus/accountabilities; Horizon 1 current
  projects; Ground: current actions.
- **Prescribed flow (bottom-up, lines 5566–5704):**
  1. **Ground**: complete the action lists (expect 50+ next actions/waiting-fors incl. agendas;
     fewer is suspect, line 5602).
  2. **Horizon 1**: finalize the Projects list (line 5606).
  3. **Horizon 2**: make and keep an Areas of Focus list (4–7 key professional areas + similar
     personally); use it to uncover missing projects (lines 5622–5640).
  4. **Horizons 3–5**: ask the listed questions ("What are the longer-term goals ... and what
     projects do I need to have in place related to them?", lines 5674–5681; ultimately "Why does
     your company exist? Why do you exist?", line 5704).
  5. Each level should align with the one above; conflicts resolve upward (lines 5533–5535).
- **Done when:** commitments are identified at every level and the user can defend, at day's end,
  what didn't get done (line 5423).
- **Cadence:** Ground/H1 weekly; H2 every 1–3 months; H3–5 as needed/annually (user-determined).
- **Citations:** lines 1641–1693, 5515–5704.

### B1-W-28 — Natural planning model (five phases of project planning)
- **Trigger/situation:** A project needs more clarity or shape than outcome + next action provides
  (vertical focus).
- **Steps in order (lines 1749–1759; techniques 1869–2212):**
  1. **Defining purpose and principles** — ask "Why?" (purpose defines success, creates
     decision-making criteria, aligns resources, motivates, clarifies focus, expands options,
     lines 1877–1948); principles via "I would give others totally free rein to do this as long as
     they ..." (line 1966).
  2. **Outcome visioning** — picture what wild success looks/sounds/feels like; "you won't see how
     to do it until you see yourself doing it" (lines 1976–2048).
  3. **Brainstorming** — externally capture ideas (mind maps, notes); keys: **don't judge,
     challenge, evaluate, or criticize; go for quantity, not quality; put analysis and organization
     in the background** (lines 2052–2140).
  4. **Organizing** — "Identify the significant pieces; sort by components, sequences, priorities;
     detail to the required degree" (lines 2144–2179).
  5. **Identifying next actions** — "Decide on next actions for each of the current 'moving parts'
     of the project. Decide on the next action in the planning process, if necessary."
     (lines 2183–2212).
  - Anti-pattern named: the **unnatural/reactive planning model** — starting with "who's got a good
    idea?", or with action-first crisis mode, then working backwards (lines 1813–1867).
- **Done when:** "as much as you need to get the project off your mind" — "If the project is still
  on your mind, there's more thinking required" (lines 2218–2224).
- **Cadence:** per project, scaled (see B1-W-31).
- **Citations:** lines 1705–2280.

### B1-W-29 — Moving up/down the planning model (unsticking a project)
- **Trigger/situation:** A project is stuck — either unclear or not moving.
- **Steps in order:**
  - **Need more clarity? Shift UP the model:** busy-but-confused action → pull out/create the plan
    (organize) → if plan untrusted, brainstorm more → if brainstorm fuzzy, return to outcome/vision
    → if vision unclear, return to purpose ("why are you engaged in this at all?") (lines
    2235–2237).
  - **Need more action? Move DOWN the model:** enthusiasm about purpose but no picture → define the
    vision ("What would the outcome look like?") → stuck after that → brainstorm the hows → ideas
    but no decisions → organize/decide mission-critical deliverables → plan exists but no traction
    → "What's the next action, and who's got it?" per component (lines 2240–2248).
- **Done when:** the project is off the user's mind and moving (line 2224).
- **Cadence:** whenever a project nags or stalls.
- **Citations:** lines 2216–2248.

### B1-W-30 — Activating a project's moving parts
- **Trigger/situation:** Verifying a project is sufficiently planned for implementation.
- **Steps in order:**
  1. A project is sufficiently planned "when every next-action step has been decided on every front
     that can actually be moved on without some other component's having to be completed first"
     (line 2202).
  2. For each component ask: **"Is there something that anyone could be doing on this right now?"**
     (line 2202). Components blocked by dependencies get no action yet.
  3. If more planning is needed first, the next action is a **process action** ("Draft more ideas",
     "Set up planning meeting") (line 2206).
  4. If the next action is someone else's, clarify whose, and track it (Waiting For); in groups,
     allocate responsibility per piece (lines 2210–2212).
- **Done when:** every independently movable front has exactly one current next action (or a
  tracked Waiting For).
- **Cadence:** per project, re-verified each Weekly Review (B1-W-23 step 8).
- **Citations:** lines 2196–2212.

### B1-W-31 — How much planning per project (the 80/15/5 calibration)
- **Trigger/situation:** Deciding whether a project needs more than outcome + next action.
- **Steps in order:**
  1. Default: ~80% of projects need only outcome + next action, with the full planning model run
     informally in the head (line 2228).
  2. ~15% need at least some external brainstorming (mind map, notes) (line 2230).
  3. ~5% need deliberate application of one or more of the five phases (line 2232).
  4. The selection test for more planning (ch. 10): projects that (1) **still have your attention
     after next actions are defined**, or (2) about which **ideas show up ad hoc** that need a home
     (lines 5786–5790). For type 1, put a planning next action on the right context list ("Draft
     ideas re X", "Organize Project X notes", set up a meeting, gather information)
     (lines 5794–5817).
- **Done when:** each project receives exactly enough planning to leave the mind ("How much ...?
  As much as you need to get the project off your mind", line 2218).
- **Cadence:** per project; rechecked weekly.
- **Citations:** lines 2216–2232, 5754–5817, 5959–5985.

## Cross-cutting principles (Part 3)

### B1-W-32 — Managing self-agreements (don't make / complete / renegotiate)
- **Trigger/situation:** An internal commitment is causing pressure; or capacity is exceeded.
- **Steps in order:**
  1. Recognize that every captured "should" is an agreement with yourself, and a broken agreement
     erodes self-trust (lines 6117–6135).
  2. Three (and only three) ways to silence the pressure: **"Don't make the agreement"** (say no,
     toss it, Someday/Maybe it), **"Complete the agreement"** (do it — e.g. via the two-minute
     rule), or **"Renegotiate the agreement"** (consciously change it — "A renegotiated agreement
     is not a broken one", line 6117) (lines 6060–6064).
  3. Renegotiation requires visibility: "it's impossible to renegotiate agreements with yourself
     that you can't remember you made!" (line 6129) — hence 100% capture and regular review are
     prerequisites (line 6141).
- **Done when:** every commitment is either undone (consciously), done, or visibly renegotiated;
  nothing is held as an implicit broken agreement.
- **Cadence:** continuous; renegotiation happens naturally each time lists are reviewed
  (line 6129).
- **Citations:** lines 6055–6193.

### B1-W-33 — "What's the next action?" as a closure standard
- **Trigger/situation:** Any discussion point, meeting end, or shared decision moment.
- **Steps in order:**
  1. Ask **"So what's the next action on this?"** at the end of each discussion point — in staff
     meetings, family conversations, anywhere (line 6446).
  2. Record the answer (and owner) into the system per B1-W-06/09.
- **Done when:** no interaction ends with an ambiguous "we should..." left unowned; "When a culture
  adopts 'What's the next action?' as a standard operating query, there's an automatic increase in
  energy, productivity, clarity, and focus" (line ~6207, ch. 12 epigraph).
- **Cadence:** every meeting/discussion.
- **Citations:** lines 6207, 6446; next-action conversation in planning at 2210–2212.

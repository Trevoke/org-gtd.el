## CAP — Capture

- **REC-CAP-01** · Capture any incomplete / open loop (personal or professional, big or small) into a single trusted inbox with zero up-front filtering or value judgment, so the mind can release it. · type: tool · strength: must · provenance: B1: A-01, B-01, D-01 · B2: A-01, B-11 · DA94: 08 · confidence: clear · keywords: inbox, capture, open loop, trusted bucket
- **REC-CAP-02** · Funnel all inputs through as few inboxes as needed and as many as necessary, kept leakproof; the tool provides one canonical capture target (`inbox.org`). Email may remain its own subsystem (conceptual, not literal, "single place"). · type: tool · strength: must · provenance: B1: A-02, B-01 (caveat l.3592–3594) · B2: A-02, D-05 · confidence: clear · keywords: inbox, leakproof, funnel, single target
- **REC-CAP-03** · Capture is available in every context / always at hand, so a thought can be recorded the instant it occurs; any file, location, or activity can be tagged into the inbox for later closure. Partly a hardware/habit prescription the tool can only meet halfway. · type: tool · strength: must · provenance: B1: A-03, C-V7 · B2: A-03 · DA94: 11 · confidence: clear · keywords: ubiquitous capture, always available, capture hook
- **REC-CAP-04** · Each captured item is its own discrete placeholder (one thought = one heading), never lumped into one running list; an item may be a textual placeholder for a physical thing. · type: tool · strength: must · provenance: B1: B-02, B-03 · B2: B-01 · confidence: clear · keywords: discrete item, placeholder, one per heading
- **REC-CAP-05** · Every item is date-stamped automatically at capture/entry time (CREATED / inactive timestamp) — load-bearing for Waiting-For follow-up timing. · type: tool · strength: must · provenance: B1: B-04 · DA94: 38 (auto-date-stamp in the unified item schema) · confidence: clear · keywords: timestamp, created date, auto-stamp
- **REC-CAP-06** · Provide a guided mind-sweep / bulk-capture action, invokable any time, driven by quick and full trigger lists (Incompletion Trigger List, the six Horizons as prompts) to externalize everything resident in head and environment. · type: tool · strength: should · provenance: B1: B-05, B-06, D-17 · B2: A-25, B-02, B-03, D-15 · DA94: 17, W01 · confidence: clear · keywords: mind sweep, trigger list, bulk capture, brain dump
- **REC-CAP-07** · Capture and clarify are decoupled: at the end of a capture session the user chooses "process now" or "add to inbox" — entering items never forces immediate processing. · type: tool · strength: should · provenance: DA94: 18 (p.4) · supports X-11 stage separation (B1 l.1035–1037, 1187) · confidence: medium · keywords: decoupled capture, process now, defer processing
- **REC-CAP-08** · Capture hooks at activity boundaries: when a communication or work session ends, optionally prompt "anything to process?" so loose ends are swept immediately. · type: tool · strength: may · provenance: DA94: 34 (p.13 post-phone-call prompt) · confidence: medium · keywords: boundary prompt, capture hook, sweep
- **REC-CAP-09** · Support a "what's true right now?" current-reality and distractions inventory as a repeatable capture practice (a themed mind sweep), distinct from the general trigger-list sweep. · type: methodology · strength: may · provenance: B2: C-V4 (l.7002, 7143; orphan adjudicated ADD) · confidence: medium · keywords: current reality, distractions inventory, themed sweep

## CLA — Clarify

- **REC-CLA-01** · Empty the inbox to zero on a regular cadence (target: every input reaches zero every 24–48 h); emptying = deciding what each item is and where it goes, not completing it. Items are processed one at a time, top item first, never skipping to easier ones. · type: methodology · strength: must · provenance: B1: A-04, B-07, C-29, D-28 · B2: D-06, D-34 · DA94: 19, W09 · confidence: clear · keywords: inbox zero, one at a time, top first, processing
- **REC-CLA-02** · An item, once picked up, never returns to the inbox undecided — a one-way path out of "in"; each item is dispatched to exactly one destination. Processing ≠ spending time on (beyond the 2-minute rule, the loop is for deciding). · type: tool · strength: must · provenance: B1: A-04, B-08, B-42 · confidence: clear · keywords: no return, one destination, dispatch, decide
- **REC-CLA-03** · For each item, first answer "What is it?" then the gating question "Is it actionable?" (yes / no; "maybe" resolves to no-but-incubate). Alternative triage vocabulary: Activate / Incubate / Eliminate. · type: tool · strength: must · provenance: B1: A-05, A-06, B-10 (corrected from B-09) · B2: A-04, B-15 · DA94: 20 · confidence: clear · keywords: actionable, gating question, triage, branch
- **REC-CLA-04** · For an actionable item, clarify captures two things: the desired outcome ("what does done look like?") and the next physical, visible action. A multi-step item can become a project inline (title outcome → next action) without leaving the processing flow. · type: tool · strength: must · provenance: B1: A-10, A-39, B-09, D-05, D-22 · B2: A-05, B-16, C-03 · DA94: 21 · confidence: clear · keywords: outcome, next action, inline project, done looks like
- **REC-CLA-05** · The next-action clarity test: an action is thought through enough when the user can answer *what has to happen first? / what does doing look like? / where does it happen?* — concrete, physical, single. · type: methodology · strength: should · provenance: B1: D-22 · B2: C-03, C-D4 · confidence: clear · keywords: clarity test, physical action, three questions
- **REC-CLA-06** · Clarify can extract inherent projects/next-actions from fuzzy attention items and unrecognized concerns; outcomes include those whose "done" is merely accepting/closing a thing with no solution. · type: methodology · strength: should · provenance: B1: C-24, D-05 · B2: B-04, C-23 · confidence: clear · keywords: fuzzy items, hidden project, extraction
- **REC-CLA-07** · Capture is non-committal: an item may be deferred, dismissed, or dropped at clarify time without forcing resolution; sensitive/emotional items run through the same flow as any other. · type: methodology · strength: should · provenance: B2: A-18, B-10 · confidence: clear · keywords: non-committal, dismiss later, when in doubt
- **REC-CLA-08** · Two-minute rule: if the clarified next action takes ≤2 minutes, do it immediately during processing rather than tracking it; afterwards, if the project isn't done, clarify the new next action and re-route. (2-minute items are *done, not stored* — the quick-action category is tool plumbing.) · type: methodology · strength: must · provenance: B1: A-11, B-16, B-17, D-16 · B2: B-39, C-05, C-06 · DA94: 12 (optional timer/alarm), W02 · confidence: clear · keywords: two-minute rule, do it now, quick action
- **REC-CLA-09** · The do-it-now threshold is configurable: the two-minute cutoff can stretch (5–10 min) or shrink (~30 s) depending on the processing window available. · type: tool · strength: may · provenance: B1: l.3946 (reader-B missed item, audit add) · confidence: clear · keywords: threshold, configurable, cutoff
- **REC-CLA-10** · List entries must remain discrete, physical next actions over their lifetime — they must not morph back into "stuff" ("Johnny's birthday", "Receptionist"); clarify (and review) maintain this invariant. · type: methodology · strength: should · provenance: B1: l.6376–6396 (reader-C missed item, audit add) · confidence: clear · keywords: anti-degradation, discrete entries, stuff
- **REC-CLA-11** · Clarify supports the three honest exits from a broken or stale agreement: renegotiate it, complete it, or consciously drop/forgive it — surfaced as a decision, never silently. · type: methodology · strength: may · provenance: B1: D-V5 (l.7238–7248, 7308; orphan adjudicated ADD) · confidence: medium · keywords: renegotiate, broken agreement, conscious drop
- **REC-CLA-12** · Daily processing must be fast: staying current costs ~30–90 min/day in the books' estimate, so the tool's per-item clarify loop is optimized for speed (minimal keystrokes, no forced forms). · type: tool · strength: should · provenance: B2: D-D7 (l.9647–9672), l.6776–6778 (orphan + reader-C missed item, merged) · confidence: medium · keywords: speed, daily budget, fast clarify, friction

## PRJ — Organize: Projects

- **REC-PRJ-01** · A Project is any desired outcome requiring more than one action step, finishable within ~1 year; it lands on a single Projects list — an index/overview (one per line, typically 30–100 open), not priorities and not the plans. The 1-year bound divides Projects (weekly review) from Goals (30k, quarterly) — a Book-1 definition; Book 2's delta is only the review-cadence justification. · type: tool · strength: must · provenance: B1: A-14, B-30, C-48, D-06 · B2: A-06, B-23, C-15, C-16, C-D7 · confidence: clear · keywords: project definition, index, one year, multi-step
- **REC-PRJ-02** · Every active project carries ≥1 defined next action; an independently movable portion keeps its own. Review (and optionally the dashboard, REC-UI-02) surfaces projects lacking one. · type: tool · strength: must · provenance: B1: A-15, A-45, B-33, C-06, C-34 · B2: C-16, D-28 · DA94: 14, 25 · confidence: clear · keywords: stuck project, next action invariant, detection
- **REC-PRJ-03** · A dependency-blocked **subproject held in support material** may legitimately lack a next action while it waits on another piece; stuck detection must not flag these. (Corrected: the source licenses this for subprojects-in-support-material only, not top-level Projects entries — every top-level project gets a kick-start action at review.) · type: tool · strength: should · provenance: B1: C-05 (corrected per audit, l.4518 vs l.5157) · confidence: clear · keywords: blocked, dependency, subproject, org-edna
- **REC-PRJ-04** · Subprojects/components are either rolled up under one Projects-list entry (detail in support material) or listed as their own entries — the user's choice; the tool forces neither. Parallel components each get a next action; sequential ones expose the single linchpin action. · type: tool · strength: should · provenance: B1: A-41, A-42, C-04 · confidence: clear · keywords: subprojects, rollup, parallel, sequential, linchpin
- **REC-PRJ-05** · Project support material, *where it exists*, is attached to the project (body/drawers/links) but kept separate from the action reminders and from the Projects index — support material never doubles as the reminder. Active-project material is kept more accessible than pure reference. (Corrected: a separation requirement, not an existence requirement.) · type: tool · strength: must · provenance: B1: A-16, B-31 (corrected per audit), C-07, C-09, D-24, l.1331 · B2: B-24, D-13 · confidence: clear · keywords: support material, separation, attachment, accessible
- **REC-PRJ-06** · Support the Natural Planning Model for projects needing more clarity or action: purpose/principles → vision/successful outcome → brainstorm → organize → next actions; ~80% of projects need only outcome + next action. Off-your-mind = planned enough. The project record can hold the NPM as a schema (purpose, outcome scenario, components/sequences, current next actions, waiting-fors, maybes, resources). · type: tool · strength: should · provenance: B1: A-38, A-40, C-49 · B2: A-22, D-25, D-26 · DA94: 22, 23, W03 · confidence: clear · keywords: natural planning, brainstorm, outcome vision, schema
- **REC-PRJ-07** · A project's next action can itself be a planning step ("process action"); a Project Planning Trigger List (resources, finance, risks, stakeholders…) is available to drive brainstorming. · type: tool · strength: should · provenance: B1: A-44, C-49 · B2: D-27 · confidence: clear · keywords: process action, planning trigger list
- **REC-PRJ-08** · A "look into" / R&D outcome is a real project as soon as there is a commitment to decide (~10% of projects start this way). · type: methodology · strength: should · provenance: B2: B-09 · confidence: clear · keywords: research project, commitment to decide
- **REC-PRJ-09** · Per-project reference/support can split into Active vs Archive compartments, while project info stays scannable from the one Projects list. · type: tool · strength: may · provenance: B1: l.4569–4577 (reader-C missed item, audit add) · confidence: clear · keywords: active archive, project folders
- **REC-PRJ-10** · Ship a project-identification verb checklist (Finalize / Implement / Research / Publish / … / Resolve) the user can run to discover their projects — parallel to the two Appendix trigger lists. · type: tool · strength: should · provenance: B2: l.7724–7749 (audit missed item #3) · confidence: clear · keywords: verb checklist, project discovery
- **REC-PRJ-11** · Personal projects are first-class alongside professional ones: same list, same review cadence; the tool never structurally segregates them (optional user subdivision allowed, see REC-X-06). · type: tool · strength: should · provenance: B2: C-17 (l.7770–7778; orphan adjudicated ADD) · B1/B2: "personal + professional" clauses of CAP-01/ENG-01 · confidence: clear · keywords: personal projects, same list, no split
- **REC-PRJ-12** · "Process projects" — outcomes whose deliverable is a recurring procedure/habit ("set up exercise routine") — clarify like normal projects and may spawn a recurring Habit on completion. · type: tool · strength: may · provenance: B2: B-V3 (promoted, self-flagged) · confidence: medium · keywords: habit, recurring, process project

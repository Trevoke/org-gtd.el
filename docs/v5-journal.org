- *Process*: pick the next item from [[* Backlog — awaiting decision][Backlog]],

- *Decision keywords* (the =#+TODO= line):
  - =UNDECIDED= — not yet reviewed.
  - =REVIEWING= — actively under discussion.
  - =TODO= — a real, committed to-do that's *tracked* (a yak), but whose exact
    release scope (v5 vs later) isn't fixed yet. Not shelved — on the list.
  - =BUILD-V5= — commit to building it for 5.0.0.
  - =DEFER= — real, but later (5.x or a future adapter layer); say where.
  - =DROP= — decided not to do; say why.
  - =DONE= — already implemented.
- *Per-heading properties*: =:REC_ID:=, =:STATUS:= (current implementation
  status: Implemented / Partial / Via-config / Not-implemented), =:STRENGTH:=
  (must / should / may), =:TYPE:= (tool / methodology), =:DISPOSITION:= (prior
  =V-xx= adjudication, if any — those are already-made calls, not to
  re-litigate), =:UX_DOC:= (whether a REC-* workflow design exists).
- *Tags*: strength + area, for filtering (e.g. =C-c \ +must+engage=).
- *Standing constraints* (do not propose against these): no org-ql /
  org-super-agenda dependency; no forced org-agenda; reference and contacts
  systems are future *adapter* layers, not bundled stores.

*** DROP REC-PRJ-07 — planning step as a next action + trigger list    :should:projects:
:PROPERTIES:
:REC_ID:      REC-PRJ-07
:STATUS:      Partial → dropped (workflow mismatch)
:STRENGTH:    should
:TYPE:        tool
:DISPOSITION: DROP + docs note; side-window idea → PRJ-06 yak
:UX_DOC:      (none)
:DECIDED:     2026-07-15
:END:
Workflow analysis killed the "ship a planning checklist" idea. Project tasks are
*typed as outline headings* in the clarify WIP buffer (=org-gtd-organize= reads
them) and added later via =org-gtd-project-operations=. A trigger-list checklist
is a separate prompt buffer with *no bridge* from "checked item" to "project
task" — walk it, discard most, and you still go type the tasks. A trigger list
is a thinking *aid* (like the horizons window), not a task source.

*Decision*: DROP the checklist. PRJ-07's value is already covered:
- adding tasks → type them in the WIP buffer (+ project-operations later);
- "planning as a next action" → when you can't plan yet, type one task
  "Brainstorm/plan project X" — nothing to build;
- brainstorming aid → a "triggers" side window, if wanted, is folded into the
  PRJ-06 clarification-UI / side-window review yak.

*Docs follow-up*: note the planning-as-a-next-action pattern in the projects docs.

*** DROP REC-PRJ-08 — "look into" / commitment-to-decide (R&D) projects :should:projects:
:PROPERTIES:
:REC_ID:      REC-PRJ-08
:STATUS:      Partial → dropped (no distinction needed)
:STRENGTH:    should
:TYPE:        tool
:DISPOSITION: DROP + docs note
:UX_DOC:      (none)

A "look into X" commitment is just a normal project whose *outcome is a decision*
("Decide whether to X" with research/compare/decide tasks), or a Someday/Maybe
item if not yet committed. Both are covered by existing types; a dedicated "R&D
project" type adds a distinction with no behavioral difference — and we
deliberately dropped =define-type=. Even the gap doc hedged "arguably fine."

*Decision*: DROP. Docs note: model "look into" work as an ordinary project with
a decision outcome, or incubate in Someday/Maybe until committed.

*Surfaced a bigger concern* (parked on [[*REC-UI-05]]): today a project whose
tasks are all DONE reads as complete/archivable, but sometimes it's merely
*under-defined* — the outcome isn't reached, it just needs new actions. The
closure prompt (REC-UI-05) is where "all-tasks-done ≠ complete; add more
actions?" should be handled instead of silent completion. Flagged on UI-05's
backlog entry.

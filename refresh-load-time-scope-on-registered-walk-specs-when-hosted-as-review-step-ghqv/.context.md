The "refresh the frozen scope" framing is wrong. Root issue: :scope conflates TWO
identities — (1) the concurrency lock (coarse, file set) and (2) the resume-checkpoint
key (walk-<name>-<md5(scope)>.eld). Once someday-review wants to be resumable, these want
different granularities: someday-review has a `list` filter, and the file set can't tell
list A from list B, so a scope-keyed checkpoint collides across selections.

Fix: SPLIT. Keep :scope for the lock (unchanged). Add optional :resume-key naming the
selection; --checkpoint-path keys on (name resume-key) instead of (name scope). Resume
identity = walk + selection. Nothing is captured at load time, so nothing goes stale —
the "refresh" problem evaporates.

Decisions: resumable set = inbox (already) + someday-review (new, :resume-key = list
filter). missed-calendar-review STAYS :resumable nil (preserves its 2026-07-19 §2
disposability decision). Hosted-in-review-step double-persist avoided by setting
:resumable t + :resume-key at the standalone start-site only, keeping the registered
template :resumable nil so review.el's own :walk-model stays sole store when hosted.
No new engine lifecycle code needed.

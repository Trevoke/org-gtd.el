Command/view steps in the guided review use a two-press protocol: first `n` runs
the command / opens the view, second `n` advances. During QA the step display gave
no hint, so it read as a possibly-stuck key.

Desired: the step should tell the user, e.g.:
  "Advance to process the inbox. You will return here — advance again when done."

Applies to all two-press step types (process-inbox, the four Get Current views,
the someday view). Source: org-gtd-review.el step rendering. Found during PR #294 QA.

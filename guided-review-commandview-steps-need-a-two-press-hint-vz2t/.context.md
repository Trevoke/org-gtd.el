Command/view steps in the guided review use a two-press protocol: first advance (n) RUNS
the command / opens the view, second advance moves on. Two related QA observations:

(A) No hint that it is two-press, so it reads as a possibly-stuck key.
(B) The wording reads as an IMPERATIVE telling the user to do something manually (e.g.
    "process the inbox"), when in fact advancing makes org-gtd DO it. It should read as
    "we are going to open the agenda now" — system-driven, not a chore handed to the user.

DESIRED wording combines both, e.g.:
  "Press n to open the inbox for processing — you will return here; press n again when done."
  or for a view: "Press n to open the agenda view; press n again to continue."

Applies to all two-press step types (process-inbox command, the four Get Current views,
the someday view). Source: org-gtd-review.el step rendering. Found during PR #294 QA.

change — split back out if desired.)

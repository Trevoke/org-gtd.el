This is a Diataxis-style documentation set for Org GTD.  It is
organized so each document serves one purpose for one kind of reader,
not a mix.  Find the quadrant that matches what you are doing right
now.

#+TEXINFO: @noindent

| Reader's intent                          | Quadrant     | Where to start                               |
|------------------------------------------+--------------+----------------------------------------------|
| "I want to learn org-gtd by doing"       | Tutorials    | [[#tutorials][Tutorials]]                                    |
| "I have a specific task to accomplish"   | How-to       | [[#how-to-guides][How-to guides]]                                |
| "I need to look up a flag or function"   | Reference    | [[#reference][Reference]]                                    |
| "I want to understand why it works"      | Explanation  | [[#explanation][Explanation]]                                  |

If you are completely new, read [[#about-gtd][About GTD]] for context, then
start with the [[#quick-start][Quick start tutorial]].

This documentation lives alongside the existing Info manual at
[[info:org-gtd]] and does not replace it.  The two are complementary:
the older manual is the reference users have been reading; this set is
organized for discoverability.

* Tutorials
:PROPERTIES:
:DESCRIPTION: Learn org-gtd by doing — guided walkthroughs for newcomers
:CUSTOM_ID: tutorials
:END:

Tutorials are guided lessons.  Each one takes you from zero to a
working result on a small example, so you can build the muscle memory
of using org-gtd before you have to figure out anything on your own.

If you finish a tutorial and find yourself wanting to do something
different in your own files, that is the cue to leave the tutorial and
look at a [[#how-to-guides][how-to guide]] instead.

#+INCLUDE: "tutorials/your-first-project.org" :minlevel 2

* How-to guides
:PROPERTIES:
:DESCRIPTION: Step-by-step recipes for accomplishing specific tasks
:CUSTOM_ID: how-to-guides
:END:

How-to guides answer real-world questions.  Each one assumes you
already have org-gtd installed and you know roughly what you are
trying to do; the guide fills in the steps.

If you don't yet have org-gtd installed, start with [[#install-and-configure][Install and
configure]].  If you don't know what you're trying to do, the
[[#tutorials][tutorials]] are a better starting point.

* Reference
:PROPERTIES:
:DESCRIPTION: Complete catalogue of commands, configuration, types, and hooks
:CUSTOM_ID: reference
:END:

Reference describes the machinery.  It is dense, complete, and
neutral — facts you look up while you work.  It is not a place to
start learning; if you find yourself reading it cover to cover, jump
back to the [[#tutorials][tutorials]] or [[#explanation][explanation]] instead.

* Explanation
:PROPERTIES:
:DESCRIPTION: Background, design decisions, and conceptual context
:CUSTOM_ID: explanation
:END:

Explanation is reading you do away from the keyboard.  It connects
the dots: why GTD, why this design, why these defaults.  Read it when
the package's behavior surprises you, or when you want a mental model
strong enough to make your own configuration decisions confidently.
